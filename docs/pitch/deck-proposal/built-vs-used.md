## Built versus used

Chorizo Power, Goodwill Michiana (Reporting track). Everything in the repo was written this weekend. The first commit is Saturday Oct 3 at 12:28 PM EDT. Victor, Dani and Orlando wrote it with AI coding assistants (listed below). Commits made with AI help carry a Co-Authored-By line.

**Built by us**
- **Ingestion engine.** It reads Goodwill's report exports (CSV and Excel) from an inbox folder and recognises each source. It parses Upright, Cash Monkey, eBay, Amazon, ShopGoodwill's periodic report, the bank file and the month-end sources. It cleans amounts and dates, and puts orders recorded in three time zones onto the right Eastern business day. It counts a report downloaded twice only once. A missing report shows as "no data", never as $0. A SQLite store keeps every nightly load.
- **Nightly pulse.** Revenue, orders and customers by marketplace (ShopGoodwill, Amazon, eBay, other) plus the e-commerce total. Each night produces a page, a CSV for Excel and an email draft for Outlook.
- **COO scorecard.** Goodwill's own 15 KPIs from their deck, in their five areas, by day, week and month. It produces a page, a CSV and a one-page PDF.
- **Month-end close.** One command runs Goodwill's six close steps:
  - It checks every marketplace payout against the report files for the days that payout covers, and matches the payouts to bank deposits.
  - It explains each open balance, or lists it as an exception with an owner and an action.
  - It writes a General Journal and an AR invoice as CSV files in Business Central's column order. Every document must sum to zero, or nothing is written.
  - It can also write the same lines as Business Central API v2.0 requests. This is a dry run: nothing is sent.
- **Portal.** HTML pages generated by Python and served by a small local web server. The close page has a file picker beside each month-end source, to add a report and run the close again. A Dockerfile builds the same thing as an image.
- **Checks.** 501 automated tests, all passing. The sample-data generators compute an answer key separately from the pipeline, and the outputs are compared with it.

**Used, not built**

  - pytest, for the tests
  - FastAPI and Uvicorn, for the local web server
- The python:3.13-slim Docker image.
- An installed Microsoft Edge or Google Chrome, run headless, to print the scorecard PDF.

  - Claude Code with Claude models (Opus 5.5, Sonnet 5.5, Fable 5.1, Haiku 4.5), for coding and docs

- Claude's Slides artifact, to make the slides; Google Slides, to submit them.

**Simulated or not done** (the slides and the pages say so too)
- **All data is synthetic, generated by us.** No real Goodwill file has been read. Upright's columns follow the screenshot in Goodwill's deck; every other file layout is our guess.
- **Delivery is assumed and simulated.** Amanda told us to assume the providers have APIs; ours are simulated. Report files land in a folder (there is no mailbox), a command stands in for the scheduler, and emails are drafts, never sent.
- **Month-end sources.** Goodwill's Controller downloads these reports by hand today; Debie Coble told us no API exists for them. We automate everything after the download: the files go in a folder, or one picker per source on the close page. In our demo, four of the nine come from simulated APIs that stand in for that download: the Jewelry report, the carriers' bank feed, the FedEx ledger entries and the Goodwill Books statement. The other five are sample files we generated. Nothing fetches a report from Goodwill's systems.
- **Scorecard.** 11 of the 15 KPIs use a simulated internal API and are badged as such. The month-over-month change compares September with a simulated August.
- **Business Central.**
  - Goodwill confirmed that its Business Central is cloud and accepts CSV uploads. Our files follow its column order, but we have not tested an import.
  - Nothing is posted. The import files have never been loaded into Business Central, and the API requests have never been sent: we have no tenant.
  - Account, customer and document numbers are placeholders, except Dept 180, G/L 40356 and 10009, and vendor V00122, which come from Goodwill's slide 38.
  - The close rules are our reading of Goodwill's deck. We have not seen their allocation workbook.
- **Scope and access.** Brick-and-mortar stores are out of scope. There is no login, so the server is for localhost only.
